1. Introdução a um Problema Real

Imagine que gere um grande sistema de comércio eletrónico e precise de gerar um relatório analítico de vendas por estado. Num modelo estritamente normalizado (OLTP), os dados estão divididos por tabelas de clientes, produtos, pedidos e itens[cite: 4]. Para montar o relatório, o banco de dados é obrigado a executar múltiplos JOINs em tempo de execução[cite: 4]. Quando a tabela atinge milhões de linhas, o custo desta operação degrada severamente o desempenho do sistema.

Neste artigo, vamos explorar porque razão a normalização nem sempre é o objetivo final e como a desnormalização introduz redundância controlada para otimizar leituras[cite: 4].

2. O Conceito: OLTP vs OLAP

Enquanto os sistemas OLTP (Online Transaction Processing) priorizam a integridade e evitam anomalias através da normalização (1FN, 2FN, 3FN), os sistemas OLAP (Online Analytical Processing) focam-se na velocidade de leitura de relatórios, utilizando estruturas agregadas ou tabelas "achatadas"[cite: 4].

    id SERIAL PRIMARY KEY,
    pedido_id INT NOT NULL,
    nome_cliente VARCHAR(100) NOT NULL,
    estado_cliente VARCHAR(2) NOT NULL,
    nome_produto VARCHAR(100) NOT NULL,
    valor_total_item NUMERIC(10, 2) NOT NULL
);
